# Decision-driven development

This folder holds the templates for the workflow this repository follows. The
record itself — the ledger — lives next door:

- `../adr/` — the decision ledger. Every decision that required a human, numbered,
  immutable once accepted, superseded rather than edited.
- `../plans/` — the plan ledger. Every accepted proposal, turned into steps that
  each end in a verifiable state.

Together they answer two different questions. `adr/` answers *why is it like
this*. `plans/` answers *how was it built*. Neither answer belongs in a code
comment.

## The workflow

```
1. Initial prompt       The human states what they want.
2. Questions            The agent asks everything it needs. One or more rounds.
3. Proposal in chat     Prose in the conversation, not a file.
4. Implementation plan  Only after the proposal is accepted. Written to ../plans/.
```

**There is no spec step.** Nothing stands between the accepted proposal and the
plan. If this repository ever grows a `docs/spec/` folder or a `SPEC.md`, it is a
mistake and `/surf:check-project` will flag it.

Step 2 is never skipped, even when the prompt looks complete. Step 3 produces no
file — a proposal is a question, not a green light, and implementation does not
start while one is on the table. A rejected proposal returns to step 2.

## Templates

- `templates/adr.md` — used by `/surf:new-adr`.
- `templates/plan.md` — used by `/surf:new-plan`.
- `templates/proposal.md` — a checklist for what the chat proposal must contain.
  It is a checklist, not a document to save: a proposal is delivered in the chat
  and is never committed as a file.

These templates are generated by the `surf` plugin and are compared against it by
`/surf:check-project`. Editing one locally will be reported as divergent.
